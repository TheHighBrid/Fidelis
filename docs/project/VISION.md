# Product vision and final expectation

## Audience and problem

Fidelis serves a creator preparing editorial portraits, Melato lookbooks, textile
macros and luxury ecommerce imagery. Generic enhancement can sharpen edges while
inventing pores, repetitive weave, warped zippers or altered brand lettering.
Manual masking every file is slow. Fidelis should make fidelity control practical
without exposing a node graph for every image.

## Product promise to earn

Provide credible photographic detail, controllable region by region, with honest
provenance and predictable resource use. Never trade the subject's identity or a
product's actual construction for a superficially sharper image.
The quality reference is the requested hybrid of controlled Clarity enhancement
and a Krea-style regional workflow. Current output has not demonstrated parity.

## Final primary journey

1. Open a supported source or batch and see exact target dimensions, local/remote
   execution policy and a real resource/cost estimate.
2. Choose Precision Packshot, Luxury Apparel, Editorial Skin or Macro Product.
   Names reflect behaviour; experimental parameters are labelled as such.
3. Review proposed skin, hair, fabric, protected and uncertain areas. Correct them
   with paint/erase and undo; unclassified regions stay conservative.
4. Run one validated texture workflow where permitted. Watch progress, cancel
   safely, and resume after interruption without duplicate generation.
5. Inspect original, precision base, raw candidate and composite on the same grid,
   including native 100/200% crops. Reblend existing passes without a new model call.
6. Export the intended colour space, alpha and precision with a reproducibility
   record. Batch work preserves recipes, errors and per-image decisions.

The current editor starts from supplied aligned base/texture PNGs. Automatic
source-to-base, generation from the browser, automatic segmentation, true native
pixel inspection and managed high-precision export are not yet that final journey.

## Non-negotiable visual behaviour

| Area | Expected result | Unacceptable result |
| --- | --- | --- |
| Skin | Plausible tonal detail appropriate to focus and scale | Plastic smoothing, gritty pore dots, invented age/marks |
| Hair | Credible strands and silhouette | Invented repetitive strands or noisy halos |
| Fabric | Weave follows material, folds and light | Pattern overlays, checkerboards or changed textile type |
| Construction | Seam/stitch/zip/hardware geometry remains true | Melted teeth, extra stitches or shifted boundaries |
| Logos/text | Lettering and placement remain authentic | Pseudo-lettering or changed marks |
| Colour/light | Garment dye, skin tone and roll-off stay photographic | Warm filters, clipped blacks or HDR halos |
| Background | Smooth or out-of-focus surfaces remain restrained | New texture on walls, floor or bokeh |

## Platform and resource expectations

The native ARM64 lane must remain useful on Android/Termux; the 8GB M1 is a real
resource target, not an assumed workstation. Expensive generative work can use an
explicitly configured worker/provider. No silent cloud upload or universal local
latency promise. Production capability is measured by device/model/output size.

## What is outside the core release

No stock marketplace, video/audio/3D suite, public credit-billing platform or
foundational model training. More adapters come after one accepted workflow.
Vercel may later host a separate reviewed front end/docs surface; the current
local filesystem/GPU worker is not made public as project-management setup.

## Success and signoff

The product is accepted only after the quality and operational evidence in
[Quality gates](QUALITY_GATES.md) exists. The repository owner supplies final
creative/release judgment after concrete results are available. Reviewers must
see both wins and failures. Dates, staffing and parity percentages are not invented.
